# 第二阶段评测报告：原始 Chimera 与新框架的数据质量对比

**状态：`EXECUTED_AUTOMATED_SCOPE_WITH_LIMITATIONS`。** 本页保留第二阶段的比较方法和证据要求；最新自动化 O/B/C 实测结果见[完整报告](glm-2026-10-15-complete/README.md)。人工专家盲评、外部参考分布和第三阶段检测器效用仍按报告中的 `NOT_MEASURED` 边界单列。第一阶段的工程可信性结果见[第一阶段报告](../stage1/README.md)。

## 1. 这一阶段要回答什么

第二阶段回答的是：在相同任务、员工、环境、预算和观察字段下，新框架生成的数据是否比原始 Chimera 更完整、更合理、更能表达攻击行为。数据质量比较完成后，第三阶段再把 O/B/C 三组数据交给同一批检测方法，验证质量差异是否转化为检测效用差异。

因此，第二阶段不把“当前框架能生成一份日志”当成结论，也不把检测器分数直接当成数据质量分数。所有 O/B/C 差异都要同时给出分母、可评价覆盖率、失败和 `UNKNOWN`。

## 2. 三组实验设计

| 组 | 生成框架 | 攻击注入 | 作用 |
|---|---|---|---|
| O：历史基线 | 原始 Chimera 的原始代码和配置 | 原始单日注入流程 | 代表论文/旧框架实际行为；不改代码、不替换注入器 |
| B：兼容对照 | 当前新框架 | 兼容旧式单日注入 | 测量工作流执行、记录和产物管理带来的变化 |
| C：最终方案 | 当前新框架 | 完整正常日程上的 LLM 多日注入 | 测量新框架多日注入策略的额外变化 |

主比较按 `B−O`、`C−B` 和 `C−O` 分别报告。`C−O` 是端到端差异，不能把它全部归因于多日注入；只有 `C−B` 才用于解释多日注入策略的增益或退化。原始 Chimera 保持真实 baseline 的意义，不能为了平衡样本而修改 O 的单日注入。

三组必须登记代码 commit、模型实际 ID、场景、角色、员工群、随机种子、工具集合、网络策略、运行时预算、原始日志 hash 和标签来源。任何一项无法匹配，都在比较表中列为混杂或 `NOT_MEASURED`。

## 3. 新框架的多日注入协议

每个员工先生成完整的正常日程，并在攻击注入前冻结。注入器向 LLM 提供员工资料、攻击目标、团队关系和这份完整日程，要求它选择一个或多个已有日期，并把全部攻击步骤按顺序分配到所选日期。LLM 自己决定攻击持续几天和具体日期，程序不固定天数，也不为了平衡而强迫每位员工攻击固定次数。

随后程序执行四项确定性检查：日期必须来自冻结日程；日期不能重复；攻击步骤必须是已知步骤；跨日期合并后必须按原定义完整覆盖每个步骤且只出现一次。每个选中日期再由现有日程编辑器生成修改版日程，并按该日期的步骤子集校验时间、顺序、冲突和攻击标记。任何一个选中日期失败，整次 campaign 不落盘。

每次 campaign 保存：

- 完整正常日程及每个日期的规范化 SHA-256；
- LLM 原始计划、日期到攻击步骤的映射和校验结果；
- 选中日期的修改版日程及 hash；
- 未选日期的正常/修改 JSON 等价证明；
- 成功、重试、失败和未执行原因。

执行器仍按“一次运行模拟一天”的接口工作。campaign 会先为所有选中日期物化攻击日程，运行某个日期时读取该日期的攻击文件；没有被选中的日期自动读取冻结的正常日程。因此，多日 episode 是跨多个员工日的一个攻击样本，而不是把一条攻击事件拆成多个独立正例。

## 4. 数据集和样本单位

样本同时保留四个层级：行为事件、员工日、攻击 episode、员工/独立运行。统计检验以员工和独立运行做聚类单位；同一 episode 的多天、多步和多次工具调用不能当作相互独立样本。

为避免“攻击很少所以模型看似很好”的问题，确认数据预先登记三种视图：

1. **自然分布集**：完全保留 LLM 选择后的真实攻击比例，测量真实低基率下的误报、告警负担和检测延迟。
2. **匹配平衡集**：为每个攻击 episode 配对同角色、相近阶段、相近日程复杂度的正常 episode，只用于比较质量和诊断，不复制样本扩大测试集。
3. **低基率压力集**：进一步降低攻击先验，专门报告每员工日误报、固定误报率下召回和平均检测延迟。

训练数据可以按预注册规则加权或重采样；验证集和测试集保留原始抽样概率。三种视图共享原始日志和真值 sidecar，发布的数据字段与真值字段分离，检测特征构建不能读取注入计划、攻击文件名或 oracle 结果。

候选规模仍以先导估计为准：3 个共同场景、12 名员工、每场景 2 个先导 run×5 天，以及每场景 6 个确认 run×20 天。每员工日“2 个任务”只是 API 成本外推假设，不是员工工作时间模型，也不是攻击注入规则；节奏指标使用完整模拟工作日和真实事件时间。

## 5. 评测任务和科学指标

| ID | 评测内容 | 主要证据和指标 | O/B/C 对比 |
|---|---|---|---|
| Q1 | 计划目标落实 | 目标 P/R/F1、阶段偏差、遗漏/额外行为、硬阶段违规数 | 共同计划和 oracle 才计算差值；缺映射报 coverage |
| Q2 | 行为与业务成果 | 独立业务成功率、隐藏测试通过率、`pass^1`/`pass^3`、禁止副作用率、重复稳定性 | 共享任务和相同初始环境下比较；仅新框架有的成果列当前专项 |
| Q3 | 交接与跨日连续性 | 实际产物生产/消费、版本和 ACL 正确率、跨日依赖完成率 | 必须有真实消费事件；收件人名单不能代替交接证据 |
| Q4 | 分布、节奏、覆盖和多样性 | KS/Wasserstein/TV、间隔和 ACF 误差、角色×阶段覆盖、近重复率、协作图统计、最差组 | 有参考分布 R 时报告 `D(O,R)`、`D(B,R)`、`D(C,R)`；无 R 只报告相对差异 |
| Q5 | 攻击语义和 episode 完整性 | 目标可达性、动作链覆盖、成功/阻断/未知比例、严重语义缺陷率 | 按相同攻击族、角色和证据等级比较；阻断攻击单独统计 |
| Q6 | 独立盲评和 judge 校准 | 四维 1–5/abstain、缺陷率、Krippendorff α、模型 MAE/κ、严重缺陷召回和 CI | 同一匿名证据包和量表；证据不足记 abstain，不记低分或成功 |
| Q7 | 汇总、成本和适用范围 | 各指标点估计、95% cluster bootstrap CI、实际 token/API/人工成本、未测比例 | 分别给 `B−O`、`C−B`、`C−O`，保留最差组和失败样本 |

质量主指标是共同充分证据下的业务内容盲评分差值和严重语义缺陷率差值；三组有同规格执行 oracle 时，再把业务成功率差值列入主表。严重语义缺陷率定义为：至少含一项由独立专家确认的严重缺陷的可评价证据包数，除以全部可评价证据包数。同一包同一事件去重；证据不足、来源缺失或三位专家无法形成确认时单列 `abstain/UNKNOWN`。

攻击检测指标留给第三阶段，但第二阶段必须产出可用真值和跨日 episode 边界。第三阶段对 O、B、C 使用完全相同的 RBF-SVM、Temporal CNN、GCN 和 DS-IID（或原论文可核验的固定实现）、相同特征契约、相同训练/验证/测试分割和相同目标先验，报告 episode Recall、15 类攻击 macro Recall、PR-AUC、ROC-AUC、Precision、F1、固定误报率下 Recall、每员工日误报和平均检测延迟。

## 6. 统计和判定规则

真实配对 run 使用配对 bootstrap；不可配对的原始发布快照使用按员工/运行聚类的两样本 bootstrap。主表对每个指标列 O/B/C 值、分子/分母、coverage、差值和 95% CI，并按场景、角色、工作流、攻击族、正常/攻击/阻断和最差 run 分层。必要时对多个主指标使用 Holm 校正；不以“`p>0.05`”宣称等价。

确认前冻结主指标、非劣界限、抽样权重、随机种子、攻击族、停止规则和缺陷 taxonomy。任何生成器、注入器、检测器或标准化规则改变都创建新的数据版本，旧报告不回写。事件数量多不能弥补独立员工/运行太少；失败和 unknown 不能删除或改写为阴性。

## 7. 费用和交付状态

当前没有启动第二阶段大规模生成，也没有调用真实 API。沿用现有成本外推：复用已取得的 O 快照时，新框架确认生成和 420 次语义评分的估算小计约 **$66.37–$101.89**；如果必须重生成 O，按原始请求结构先导实测，不能用当前框架单价冒充，双方同价只是约 **$132.20–$203.59** 的条件量级。人工独立评分约 36–72 人小时，准备、招募、仲裁和算力另计。详见[成本 JSON](../../stage2-cost-estimate.json)和[任务/成本明细](../../stage2-tasks-and-cost.md)。

正式运行后，每个版本至少交付：`study_manifest`、O/B/C provenance、正常日程和 campaign manifest、标准化事件、失败/拒绝记录、攻击真值、分割清单、盲评包和原始评分、逐请求 usage/cost、指标与 bootstrap 样本、报告和数据卡。当前所有结果表保持 `NOT_MEASURED`，不会用第一阶段通过率填充第二阶段质量结论。

## 8. 当前结论

第二阶段的比较主线已经确定：原始 Chimera 作为不改动的 O，B 用来隔离新框架执行能力，C 用来评估完整正常日程上的 LLM 多日注入；数据质量比较完成后，再用相同检测方法验证效用差异。由于来源、确认数据和独立评分尚未生成，本报告现在只能说明方法和证据边界，不能宣称哪一组质量更高或检测更有效。
