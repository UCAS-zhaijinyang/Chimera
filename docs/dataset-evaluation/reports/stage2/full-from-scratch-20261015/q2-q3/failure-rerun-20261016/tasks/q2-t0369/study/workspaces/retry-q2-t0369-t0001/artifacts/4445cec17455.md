Design document for compute(a, b) arithmetic mean feature.

## Goal
Provide a Python feature that computes the arithmetic mean of two finite numeric inputs via compute(a, b) in src/main.py, with the core logic implemented in mean_values(a, b) in src/helper.py and reused through an import. A unittest in tests/test_compute.py verifies the documented behavior.

## Requirements
1. src/helper.py defines mean_values(a, b) returning (a + b) / 2.
2. src/main.py defines compute(a, b) that imports mean_values from helper and returns its result.
3. compute(2, 3) must return 2.5 (true division, not integer division).
4. Zero, negative and fractional values must be supported, e.g. compute(0, -4) == -2.0, compute(-1.5, 2.5) == 0.5.
5. Inputs must be finite numbers (int or float, excluding bool); non-numeric or non-finite inputs (NaN, inf) raise ValueError.
6. tests/test_compute.py contains a unittest.TestCase asserting compute(2, 3) == 2.5 plus additional coverage for zero, negative, fractional and error cases.

## Architecture
- helper.py is the pure computation module: mean_values(a, b) performs validation (finite numeric check) and returns the arithmetic mean using true division.
- main.py is the public entry point: it imports mean_values from helper and delegates; compute(a, b) is a thin wrapper so the public API stays stable.
- tests/test_compute.py uses the standard library unittest module and imports compute from src.main.

## Validation plan
- Run tests/test_compute.py with unittest.
- Run the public behavioral check: /opt/anaconda3/bin/python checks/public_check.py.
- Build with /opt/anaconda3/bin/python -m compileall -q src.

## Edge cases
- Integer inputs must produce a float mean (2, 3 -> 2.5) via true division.
- Negative and zero inputs are ordinary finite numbers and are accepted.
- bool is a subclass of int but is rejected as a non-numeric-meaningful input to avoid ambiguity.
- NaN and infinity raise ValueError because the mean would not be a finite number.
