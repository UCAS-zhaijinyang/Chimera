# 第三阶段：相同检测方法下的训练数据效用对比

状态：**任务与报告设计，尚未执行。** 目标：将训练数据从原始Chimera O换成当前框架N，保持检测方法及评价条件一致，验证检测效用差异。共用第二阶段确认数据，不重新为每种检测器生成数据。

## 1. 主实验是什么

| 固定条件 | 安排 |
|---|---|
| 主检测方法 | 原论文RBF-SVM、Temporal CNN、GCN、DS-IID，名称已核验，实现/配置待冻结 |
| 变化因素 | 训练数据O_train或N_train，两套独立训练实例 |
| 输入 | 同一个方法用共同可观察字段、窗口/图规则、预处理；新血缘/图扩展另作消融 |
| 训练规模 | 匹配正常观察单位与独立攻击episode；未知标签不当正常 |
| 调参 | 同代码/架构/搜索空间/预算；默认同冻结V_common选参数与阈值 |
| 测试 | 同一个冻结target，原阳性率不重平衡，测试标签不调参 |
| 统计 | 同target上的配对预测差值与95%CI，按实际独立组/episode重采 |

同方法指同架构、实现和协议，两源各自重新训练，并非使用相同权重。SVM/CNN/GCN/DS-IID之间可以有各自原生表示，但每方法的O/N输入语义与处理一致。CNN不能偷看未来窗口；GCN训练不能传入测试标签/未来边；DS-IID训练目标按原实现冻结。缺少输入或模型实现则未测，不用便宜模型或伪造图替换。

## 3. 共同target如何选择

优先在先导后冻结一个标签与共同模态充分的独立外部持有集；两源训练都测试该集。CERT支持外部合成转移，TWOS支持人类竞赛转移，授权企业日志才支持企业TSTR，分别命名。

没有合格外部数据时，固定T_common=O_test与N_test两个独立holdout域的共同池；O训练与N训练均测试两个域，分别报告和预注册50/50域宏平均，域内阳性率保留。这只是内部合成持有对比。不能用“O训练在O_test”“N训练在N_test”的两个分数直接宣布优势。

O/N生成与质量确认后不挑有利target。验证集用于选阈值，测试集保持盲；公共快照无独立run就用真实用户群/时间/episode组织分割。跨天窗口、跨人协作和近重复造成的桥接需要审计。

## 4. 科学指标与判定

主报告AP（连续分数的average precision）和固定审查预算Recall@k，差值统一为N训练−O训练。同时报告目标阳性率、正例员工日及独立episode数；FPR降低为改善，差值方向表中写明。F1等阈值指标只用验证阈值，不能选择测试最优F1。

四方法主结果全部报告，包括退化、未测和最差组。质量与检测分别结论，检测高分不能把缺少成果证据补成业务正确。固定主方法和主target，预注册主指标、实用差异/非劣界限及多重检验；CI跨界限则INCONCLUSIVE，不把p>0.05当等价。

普通paired bootstrap只重用同一target的预测，反映冻结训练条件下测试不确定性。训练生成不确定性另重采训练run并重新训练；seed变化不能替代独立生成run。少阳性/少独立组时扩样或限制结论，不能用巨大事件量缩窄CI。

确认前冻结同一组配对训练seed（候选5个）及每seed的验证阈值选择规则。每seed分别算O训练、N训练的指标和差值，主表用全部预定seed的指标算术均值及平均差值，同时保留逐seed结果、标准差和范围；不得挑最优seed或平均预测分数后暗中作为集成模型。内部双域先按每seed计算各域指标，再用固定50/50权重宏平均，最后平均seed。主95%CI条件化于这组冻结已训练模型：每次bootstrap对所有seed和两训练源使用同一target组/episode重采索引，重算逐seed指标再平均，seed不在主bootstrap中重采；训练seed变异另表，训练数据生成不确定性另做外层训练组重采并重训。确定性方法可复用经核验完全相同的拟合，记录重复对应，不把重复结果当额外独立样本。预定seed运行失败必须报告并重跑；未补齐不得选择性删除后填完整主结果。

主用户日评分按日终计算；延迟只能解释为日终批处理延迟。若增加30分钟滚动实验，另固定窗口与阈值，只用当时已观察事件。

## 5. 成本如何计

检测训练不调用DeepSeek；四主方法不是LLM评分器。**新增检测API费$0**，但CPU/GPU、存储、实现/特征适配、外部数据准备有成本。数据生成在第二阶段记一次，第三阶段不重复收费。

起步工作量例算：2训练源×4方法×（5参数候选×3组内训练CV＋5最终seed）＝**160次模型拟合**，还需共同验证、预测和审计。5候选/3折/5seed是待先导冻结的预算起点；独立组不足不能强做3折，确定性SVM无需重复相同seed训练。CPU调试模型不能替代四主方法的确认结果。

`C_compute = Σ方法(拟合次数×实测每次小时×设备小时价) + 特征/预测/审计/重采样成本`

| 成本项 | 当前可给出的数值 | 处理 |
|---|---|---|
| 额外生成同一数据 | $0 | 与第二阶段复用 |
| 检测模型API | $0 | 传统/深度检测器本地训练 |
| 四方法训练与预测 | 暂无金额 | 每方法先导测CPU/GPU小时，按机器报价算，不假设都能廉价CPU跑完 |
| 普通测试置信区间 | 本地计算 | 复用预测，不为每次bootstrap重新训练 |
| 训练生成不确定性、负控制和消融 | 增量训练量另计 | 不包含在基础160拟合示例中 |
| 工程/参考数据/存储 | 尚未定价 | 工时与许可/云设备报价单列 |

[第三阶段成本JSON](stage3-cost-estimate.json)保留这些口径。实际执行前冻结算力预算和质量条件；费用不足则先导/未测，不能换掉主检测方法后称已完成原比较。

## 6. 交付与结论

保存四方法代码/依赖/config、共同字段与split hash、原始连续分数、阈值出处、训练/预测账本、差值CI、负控制、分域/分层、未检出删失及未测原因。主表每行是一种固定方法下的O训练与N训练，测试来源和hash相同。

最终只能按实际证据说“在某个共同target和这些固定方法上，N训练相对O训练的AP/预算召回变化为多少”；只有满足预注册实用优势及CI才声称改善。内部合成target不声称真实企业有效，未获得原始来源或模型实现时不填写分数。
