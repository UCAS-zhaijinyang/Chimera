# 原始 Chimera 与新框架的共同攻击能力及注入协议

对比主线是三组：O 原版 Chimera、B 新框架兼容旧式单日注入、C 新框架完整正常日程上的 LLM 多日注入。三组分别生成或登记数据，最后使用相同检测方法检验效用差异。应保持工具能力、环境、攻击要求、模型、工作时段与预算规则可比，让 `C−B` 主要反映多日注入，`B−O` 主要反映新框架执行/记录能力。

## 原版依据

- [NDSS论文](https://www.ndss-symposium.org/wp-content/uploads/2026-f375-paper.pdf)
- [作者项目页](https://sites.google.com/view/chimerallm)
- [作者源码](https://github.com/fish98/Chimera)，固定revision `d732f4cb427eed9c70e8b7ee062f56eec71007ab`。
- [原工具源码包核验](evidence/original-tool-contracts.json)：本机作者camel.zip/owl.zip有完整hash；原11注册工具与已安装Camel的参数和函数体AST一致。新适配器自身的实现差异另行测试，不用这个AST核验冒充适配器字节相同。
- [15类 canonical 规格](evidence/original-attack-specs/)包含50个 how 步骤；当前原定义中3项有语义变化，正式 O/B/C 必须使用同一 canonical 副本，不能各用不同要求。

## 三组执行路径

O 保持其冻结版本的计划器、原始 OWL/Camel 任务执行和单日注入；模型配置、相同环境、日历及只读采集适配器作为外部实验配置，不移植新 router。B 使用新框架的兼容单日入口。C 使用新框架的多日 campaign 入口；报告、开发、修复流程保留作显式结构化选择。原版不为对比而改成多日注入。

按用户2026-10-13指示，两套框架取消Google/DuckDuckGo搜索，共同改用Brave的网页/图片/视频搜索。原11工具的历史核验不回写，当前搜索两项合为一项，共10项基础注册。详见[共同搜索协议](search-provider-protocol.md)；真实Brave验收尚缺独立搜索key。

两套环境应从同一模板分别初始化，分别保留自己的跨任务/跨日业务状态，且拥有同样的文件、账号、权限、网页、服务及正常同事协作条件。相同攻击要求不等于复制另一源已生成的日志或工具调用序列。

## 注入内容与时间

[固定注入清单](attack-injection-manifest.json)定义共同的场景/run/员工规模；O/B/C 使用同一高层规格。09–18工作窗口、12–13午休，8小时为可用工作容量，不是固定每人每天2个任务，也不是保证8小时都在执行工具。18–21保留事后/下班窗口。运行前显式覆写默认日历配置，并核验等待队列、worker结束和跨日状态。

每 run 安排15个攻击 episode 和31个触发员工日；8类重复攻击的3次尝试属于同一 episode，统计时按 episode/run 聚类。各组的 episode 和触发员工日都不能声称为完全独立样本。角色资格、种子、日期及 train/validation/test 按 manifest 固定。

O 继续使用原始单日注入。B 兼容这一行为。C 先生成并冻结每个员工的完整正常日程，再把整份日程交给 LLM，由 LLM 自己选择一个或多个已有日期并按顺序分配全部 how 步骤。程序只验证日期、重复、步骤完整性、时间窗口、冲突和步骤顺序；不固定攻击持续天数，也不强迫每个员工攻击固定次数。只有选中日期被修改，未选日期保持正常 JSON 等价；全部选中日期成功后才原子落盘。日程注入仍保留 AttackSteps，并在验证后确定性绑定 canonical 步骤原文到 Activity。执行器实际消费 Activity，不能仅凭编号齐全宣布未漏步骤。邮件引发的日程更新必须保留该绑定，否则拒绝更新并保留原计划。

正式数据生成时只传攻击目标、canonical要求及所在环境的真实资源信息，由各自模型选择动作。不得把第一阶段`lab_actions.py`、明确的测试操作名或预写调用序列混进正式自然员工数据。当前第一阶段的固定可执行操作用于验收工具与记录正确性，不用于自然攻击成功率、逼真程度或检测效用。

## 真值与验收

每个episode区分计划、触发、尝试、完成/阻断和实际后果。结合实际工具调用、参数/顺序、接收端、文件/数据库状态建立私有真值；模型自述和completed状态不能单独作为成功证据。缺工具、缺认证、模型拒绝、连接失败或步骤未执行都不算“预期阻断”。检测公开数据剔除攻击真值、操作名称、脚本标签及直接泄露标签的身份字段，真值放独立sidecar。

第一阶段已用真实本地文件、SQLite、HTTP接收端、Chromium验证15类机制的可执行覆盖。真实OS破坏/权限提升/恶意软件/窃取真实口令/真实DDoS/TLS外传信道未在此环境实现，使用明确披露的合成替身；这些结果不证明与原论文真实攻击细节完全等价。正式两源必须使用相同替身/环境边界并披露，或在独立隔离环境扩展两源能力后再比较。

启动第二阶段前仍需完成实际外部搜索服务验收、原版执行适配器、日历/worker生命周期联测、共享环境角色权限、发布数据去泄漏和两源独立采集检查。第一阶段受控工具通过不能自动解除这些正式生成闸门。当前未启动两套正式大规模数据生成。
