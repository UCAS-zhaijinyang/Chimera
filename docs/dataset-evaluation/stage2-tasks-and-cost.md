# 第二阶段：原始 Chimera 与当前框架的数据质量对比

状态：**任务与报告设计，尚未执行。** 主线已确认：先比较 O（原始 Chimera）、B（新框架兼容旧式单日注入）和 C（新框架完整正常日程上的 LLM 多日注入）的数据质量，再用同一组检测方法比较检测效用。来源、共同字段与 target 规则以[比较协议](comparison-validation.md)为准。

O 保持原始代码和原始单日注入，不能为了样本平衡修改；B 用来隔离新框架执行/记录能力；C 用来测量多日注入策略本身。主差值固定报告 `B−O`、`C−B`、`C−O`，不能把 `C−O` 全部归因于多日注入。

**目的：回答当前数据在哪些共同可评价的质量维度改善、退化或证据不足，并单列新增可核验能力。** 不把关闭当前workflow开关、第一阶段旧失败数据或“原描述重放”当成原始框架数据。

## 1. 先准备公平比较的数据

1. 登记O的原始发布快照或固定原版commit复现，核对许可、hash、模型、场景、人数/时长、标签及观察模态；有快照不重复生成。
2. 冻结B/C的确认生成版本与匹配高层业务规格。使用原始快照时不能重新操纵O的场景；选择共同可比范围，记录剩余混杂。
3. 建立只读标准化：相同事件定义、角色/部门映射、用户日边界、时间/通信字段、标签证据与缺失规则。适配不移植新机制进原版。
4. O/B/C 都检查 L0；保留错误、拒绝、unknown 和覆盖，原版格式缺字段要公开，不伪造 manifest 或实际成果。
5. 冻结独立 run/员工群/episode/模板分割，共用第三阶段训练、验证和 holdout 数据；外部 target 不参与生成或 judge 调参。

新框架 C 的生成顺序固定为：完整正常日程生成并冻结 → LLM 读取完整日程并选择一个或多个日期/步骤 → 程序校验日期、步骤和顺序 → 仅修改选中日期 → 全部选中日期成功后原子落盘。未选日期直接保留正常日程；攻击持续天数由 LLM 决定，程序不固定天数。每个 campaign 保存正常/修改日程、hash、原始计划、日期到步骤映射和失败记录。执行器仍按单日运行，多日 episode 通过跨日 manifest 连接。

新增数据两阶段只生成一次。共同字段比较与当前特有能力分表；原版无成果文件时相应业务oracle无法横比，不判0分。现在原始来源与确认数据尚未冻结，见[manifest模板](comparison-manifest.template.json)。

## 4. 主要指标与科学判定

主质量比较预注册共同证据下的业务内容盲评分差值与严重语义缺陷率差值。若双方具备同规格执行oracle，再将独立业务成功率差值列主指标；否则单列受限/当前专项。其他维度和分布/覆盖指标解释变化，不以单个距离或总评分盖章。

每指标记录原版值、当前值、差值方向、95%CI、分母、可评价比例、场景/角色/流程/攻击族及最差组。评分高不抵消业务硬错误；没有外部R不能声称真实企业分布保真。

严重语义缺陷率定义为：至少含一项独立确认严重缺陷的可评价证据包数／全部可评价证据包数，取值0–1。严重性标准、taxonomy和证据要求在确认前冻结；同包同一事件/类型的重复标注去重，多项缺陷也只计一个有缺陷包。3位专家先独立判断，同一证据缺陷至少2人确认且至少2人认为包可评价才进入确认；其余争议交盲化仲裁，未解决记abstain/UNKNOWN。证据不足不能记无缺陷，单列可评价coverage、abstain及分来源原因，主比较限定共同可评价范围。缺陷数量另报“每100可评价包缺陷数”，不混入主比例；原始判断、仲裁与去重记录均保留。

真实配对条件用run/任务组配对CI；不可配对公共快照用分组两样本CI。α是评分可靠性；候选α≥0.80较可靠，0.67–0.80暂定；模型候选MAE≤0.5、严重缺陷召回≥0.90且95%下界≥0.80均须先导冻结、样本量支持。否则保留人工主表、模型只诊断或INCONCLUSIVE。

质量差异/非劣界限在确认前冻结，多主指标必要时Holm控制。未知/失踪与不适用不替换为成功或失败；不能删除低分run或用事件数伪造独立样本。改生成器后新建确认数据版本，旧结果继续保留。
