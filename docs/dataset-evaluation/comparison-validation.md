# 对比实验与外部有效性验证

本文件补充三阶段评测的比较设计：不仅检查 Chimera 自身是否运行正确，还检验它相对独立生成方法的优势，以及生成数据在外部检测任务中的用途。本文件是待实施方案，尚无实验结果；所有付费模型仍只使用 DeepSeek。

## 要证明什么，以及什么证据才够

| 问题 | 主要证据 | 能支持的结论 |
|---|---|---|
| 工具执行改造是否有价值？ | 固定规划的新旧 Chimera 对照、独立任务 oracle、相同 target | 对当前改造的增益，不能代表优于其他生成方法 |
| 是否优于更简单或独立的生成方法？ | 规则/模板、单轮 DeepSeek、可选统计生成器，共同特征与预算下比较 | 在已测任务和成本条件下的相对优势 |
| 是否能用于框架之外的数据？ | 所有训练源都测试同一个 CERT、TWOS 或真实企业持有集 | 分别支持 S→S、S→human-collected 或 TSTR |
| 是否能帮助已有检测任务？ | 原数据、重复采样、原数据+不同合成源的受控增强实验 | 合成数据的增量价值，排除仅增加样本数的解释 |
| 增益来自有效信息吗？ | 独立专家、负控制、跨检测器、未见攻击族与表示消融 | 减少标签捷径、单模型偶然性及模板记忆的解释 |

外部数据、独立算法、专家审查提供不同证据，不能互相替代。多个检测器在同一 Chimera 测试集上得高分，仍不能证明外部有效。以下实验嵌入“数据可信 → 行为与成果合理 → 威胁检测效用”的三个阶段，不新增一个总分。

## 第一阶段：固定比较对象与独立证据

### 1.1 基线清单

生成基线与参考数据分开：CERT/TWOS 是外部参考/测试来源，不是本轮实现的生成算法。B 编号表示待比较的生成条件。

| ID | 条件 | 实现与输入 | 主要用途与限制 |
|---|---|---|---|
| B0 | legacy Chimera | 当前仓库 legacy 路径，冻结规划/模型/场景 | 保留原主比较；不是独立于 Chimera 的方法，也不是论文原始日志复现 |
| B1 | 规则/模板仿真 | 独立脚本按角色、工作日、活动转移、部门通信和预定攻击规则产生事件；固定模板与种子，不调用 LLM | 低成本独立生成基线；规则手工制定或仅从允许的训练参考估计，逐项公开；不用 Chimera 工作流允许边充当真实性标准 |
| B2 | 单轮 DeepSeek 日志生成 | 相同组织/角色/日计划/攻击目标，用独立 prompt 直接生成结构化用户日，不运行多智能体协作或工具链 | 比较是否需要完整框架；生成文字没有真实产物/执行状态，不声称业务成功，不补造 manifest |
| B3 | 可选 CTGAN | 仅在共同 user-day 表格空间拟合允许的参考训练数据，按 P06 固定代码版本/配置 | 检验传统统计生成是否已经足够；不是完整日志/产物生成器，L1/L2 不适用 |
| B4 | 可选 TimeGAN 或 DoppelGANger | 二选一，在允许的参考训练数据上拟合共同时间序列，按 P07/P08 固定配置 | 检验时序统计方法；本地非 LLM 算法，另计训练 compute，不要求复现完整组织链 |
| B5 | workflow Chimera | 当前框架新工作流路径，固定规划/DeepSeek 实际型号/场景 | 被评条件；共同特征比较与新增血缘/图表示增益分开 |

B1/B2 是优先补齐的独立基线；B3/B4 在参考训练量、实现及计算预算可用时作为扩展，缺失则标 `NOT_MEASURED`。不能只选择明显错误的手写日志作为竞争方法；先用训练/验证集给各方法相同调参机会，并公开规则、prompt 和失败结果。

B1 若使用 legacy 训练统计，必须写明依赖，不能称其完全独立的数据来源。B3/B4 若使用 CERT_train，就明确它们具有参考训练数据访问权；Chimera/B2 未访问同等信息时，分为“零样本规格生成”和“参考辅助生成”两组报告，不能把差异全部归因生成机制。

独立统计生成器的随机输出批次不自动构成独立拟合run；若要评价生成/拟合过程的变动，重采允许的训练群体并独立重拟合。只从同一拟合模型多抽行时，CI仍对该拟合条件化；不要将分批导出文件当作独立训练样本。

### 1.2 共同数据与标签契约

先固定比较所有方法都能提供的可观察字段，例如员工日事件数、模态占比、工作时段、设备/对象数及通信统计。角色/部门只有在外部参考确实提供且能映射时纳入；没有的字段不由模型补齐。事件定义、可观察攻击口径、聚合窗口、缺失处理、特征版本、观察量和训练规模写入 manifest。

各方法接受相同 L0 检查：坏行、失败、未知与未捕获攻击显式保留。能实际执行的条件用执行/状态证据验证标签。B2 的攻击目标和生成器自报标签仅代表意图；独立审核只能确认日志文本中可观察的模拟攻击，不能证明工具执行。没有同口径可审计标签的生成源，先纳入**仅正常数据训练的异常检测比较**；未完成独立攻击证据审核前，不纳入有监督主比较。只生成正常数据的配置也需检查混入攻击或未知行为的情况，不能将 unknown 默认填正常。

规则仿真的状态与标签由独立规则轨迹记录，发布为仿真证据；文字生成与 CTGAN 没有成果/血缘时，相应项标 `NOT_APPLICABLE`，不以空 manifest 填满验收。下游比较报告每个源的标签证据等级，不能把“有意生成攻击”和“可观测执行攻击”混成一个阳性定义。

### 1.3 外部参考的角色与获取门禁

| 来源 | 在比较中的角色 | 分割与证据边界 |
|---|---|---|
| CERT，固定实际可得版本 | 外部合成分布、攻击覆盖与检测 target；可另提供训练参考 | 按用户/episode/时间或独立场景分组并检查桥接；称 S→S，不代表真实企业 |
| TWOS，获得文件及许可后 | 人类竞赛行为参照及独立检测 target | 先核对字段、标签与参与者依赖；称 S→human-collected，不代表生产企业 |
| 授权真实企业日志 | TSTR、数据增强和运营误报 target | 来源/标签/用途经确认，train/validation/test 严格分离；没有阳性证据只评正常误报，不补造检测召回 |
| 人工编写、私有持有的任务/攻击 fixture | 独立 oracle 与行为边界挑战 | 答案及隐藏功能测试不提供给生成器；与自然分布数据、公开模板测试分别报告 |

外部 train/validation 可以在预注册的参考辅助实验中用于拟合、适配及选阈值；外部 test 不能用于生成、规则调整、模型选择、judge 校准或挑选合成样本。先导揭盲的参考只能用于开发，确认须另有未揭盲 target。TWOS 样本或独立群体不足时保留探索性结论，不靠拆更多日志行增加独立样本。

外部快照不可得时，仍实施 B0/B1/B2/B5 在共同双域 target 上的比较，但结果表必须写“外部转移未测”，不能以内部留 run 替代外部有效性。

## 第二阶段：比较行为与成果是否合理

### 2.1 同一标尺、按能力比较

1. **共同字段质量**：B0–B5 在同一参考、相同观察量和特征空间上计算 L3 的条件分布、时序、覆盖、重复与来源可分性。CTGAN 不提供顺序时，时序项不适用；来源分类器接近随机不等于数据一定有效。
2. **共同内容盲评**：B0/B1/B2/B5 的日志片段采用相同上下文和长度上限，专家隐藏来源后评内容、角色和时间/协作；B3/B4 仅有数值特征，不做邮件语义评分。共同日志盲评与完整轨迹/成果评分分别报告，避免丰富上下文本身成为条件差异。
3. **成果与机制验证**：可实际执行的 B0/B5 在相同隐藏 fixture 上用独立 oracle 检查完整业务成果。对没有执行能力的基线不计算虚构成功率；B0/B5 的机制改造由原黄金任务和规划消融回答。
4. **质量与成本关系**：共同特征主比较先匹配员工日/正常观察量；另报同等总生成费用下的检测效用曲线。两种预算回答不同问题，不能同一表里混用；新增产物/图的价值单独做表示消融。

沿用 L3/L4 指标与置信区间，不新增任意“综合真实性分”。参考校准、最差角色/场景和未知/失败比例均保留。比较某一方法缺失的能力时，报告能力差异及不适用项，不将它自动记满分或零分。

### 2.2 独立专家样本的增量

原 60 校准包+180 确认包、每包三专家的协议保留。另建共同日志确认样本：3 场景×4 源（B0/B1/B2/B5）×10 包=120包，每包3名专家，共360次评分；按每次3分钟例算新增18人小时。每 cell 良恶各5包仅作平衡诊断，失败及少数角色继续分层抽取，不改变检测测试阳性率。数量为先导起点，不能保证功效。

原轨迹包仅在确认抽样、上下文、盲化和量表与本实验完全一致时复用；否则单列，不把已经揭盲评分拼为新独立样本。CERT/TWOS 的外部日志盲评在模态和上下文可对齐时另设样本与预算，不能冒充上述三种模拟业务场景。无法支持人工对比时，相对语义优势标不确定，不能仅用同厂 DeepSeek 的偏好代替。

## 第三阶段：外部检测与增量效用实验

### 3.1 实验矩阵

| ID | 比较与固定条件 | 测试集 | 主要问题 |
|---|---|---|---|
| E0 改造对照 | B0 vs B5；相同规划/模型/训练观察量/检测器 | 所有条件都测试 target_legacy 和 target_workflow，分别报及固定50/50宏平均 | 新工作流是否改善自身体系；保留原主实验 |
| E1 独立生成基线 | B0/B1/B2/B5；可选B3/B4；共同特征，同等样本主比较、同等成本次级比较 | 同一冻结双域 target；可得时另加每个外部 target | 是否相对独立方法有优势 |
| E2 外部直接转移 | 各合成源单独训练，固定检测器；正常-only 与合格有监督实验分开 | CERT_test、TWOS_test、真实 R_test 分域报告 | 是否在非 Chimera 来源上有效 |
| E3 数据增强 | R_only、R+duplicate、R+各合成源；合成增量K相同 | 同一个外部 R_test | 是否补充原数据，而非仅增加样本数 |
| E4 覆盖与样本效率 | 不同训练量；留场景/攻击族/任务模板；固定同一预算 | 相应未见场景/攻击族 holdout | 是否支持稀缺样本与新威胁 |
| E5 交叉印证与负控制 | 多检测器、随机标签、元数据-only、去模板/结构消融、私有配对挑战 | 相同冻结 target；挑战集单列 | 高分是否依赖捷径或偶然的检测器选择 |

E1/E2 主比较先采用正常-only Isolation Forest 与另一种预注册轻量异常检测器，例如 One-Class SVM。各方法匹配正常观察量；正常训练仍须有审计依据。通过标签证据与语义对齐的源，另用 logistic regression、RBF-SVM、轻量树模型做有监督比较，匹配正常数量与独立攻击 episode 数并分列。正常-only 与有监督结果不能合成一个排名。

不是每种数据都支持 episode/延迟等指标：外部参考缺首次可观察攻击时间时，只报可支持的 AP/预算召回/FPR，并将延迟标未测。用户日和 episode 真值不能直接互换，标签映射过程及损失需记录。

### 3.2 直接转移与参考内训练锚点

对每个可得外部来源 R，固定 R_train/R_validation/R_test。所有合成源均测试同一个 R_test；训练参考、测试快照不得有同用户/episode/模板桥接。表中训练源与适配方式必须分列：

| 训练/适配条件 | 用途 |
|---|---|
| S_train；仅源验证集选模型/阈值 | 零目标适配转移；没有借目标标签选阈值 |
| S_train；允许固定 R_validation 选阈值/适配 | 参考辅助转移；不能与零适配混报 |
| R_train；R_validation 选模型/阈值 | 参考内训练锚点，真实数据时称 TRTR；不是理论上限 |
| S_train → S_test | 同源可学性诊断；不能替代前三项 |

CERT 的参考内训练写 C→C，TWOS 写 H→H；只有真实企业 R_test 才使用 TSTR/TRTR 术语。不同目标来源的阳性率和难度不同，分别报告 AP、Recall@k、FPR、正例/episode 数及差异CI，不直接平均跨数据集 AP 作排名。

核心效应为同一 target 上 `ΔAP(source,baseline)` 和 `ΔRecall@k(source,baseline)`。参考内训练锚点用于解释迁移差距，不把“达到锚点的某个比例”作为通用质量门槛。若源标签与目标攻击语义不一致，只评重叠子任务并报告覆盖，不能将未覆盖攻击全部从完整 target 中删除后宣称覆盖全面。

### 3.3 数据增强与少样本价值

优先对可得的 CERT/TWOS 做增强方法试验，结果按来源命名；有授权真实数据时再验证真实企业增量效用。每次固定相同 R_train 子集、相同 R_validation 和 R_test，使用以下训练条件：

- `R_only`：原训练样本。
- `R+duplicate`：从 R_train 简单重复采样，增加 K 个样本；排除仅由更多训练行/迭代造成的改善。
- `R+rule / R+single-shot / R+Chimera`：分别加入 K 个可审计合成样本；可用时增加 CTGAN/时序生成器。

有监督组匹配合成正常量、攻击 episode 量与类别权重；无合格阳性标签的源仅进入正常-only 增强实验。不能只通过改变训练阳性比例改善召回而不对比同阳性数的重复采样。主测试保持原有阳性率，固定告警预算/验证阈值；检测器训练迭代和调参机会一致，记录实际训练compute。

训练数据稀缺曲线候选为 10%、25%、50%、100% 的独立训练单位，以及 `K/原训练样本量=0.5、1、2` 的增强量；先导后冻结主比较为一个预注册训练比例和 K，其余探索性。按用户/run/episode 成组抽取，保留合法时间顺序与最少阳性，比例不足则该点未测。每个点仅离线重训，不重复调用 LLM 生成同一批数据。

合成输入只能来自公开业务规格或该条件允许的 R_train 信息；外部测试攻击模板和答案不得传入 prompt。只有 `R+Chimera` 在相同 target、预算下相对 `R_only` 与 `R+duplicate` 都有预注册的实用增益，才支持增量价值；只优于前者时排除不了样本量解释。

### 3.4 多路径印证与负控制

| 检查 | 实施 | 解释边界 |
|---|---|---|
| 跨检测器一致性 | 固定同一数据，用线性/核/树检测器；异常检测另成组 | 效应方向、大小、区间分别报告；只对一个模型有效则限制结论，不能做多数投票总分 |
| 随机训练标签 | 保持特征与类别数量，在独立训练单位层面置乱训练标签；验证/测试真值不变 | 除确定性记忆模型外按多个预注册随机种子运行；比较 AP 与目标阳性率/置乱分布，不期待精确等于基线 |
| 元数据/模板捷径 | metadata-only、去路径/注入文案、仅共同字段，所有处理仅在训练阶段制定 | 捷径解释排除前不声称有效；不以来源可分性直接判标签泄漏 |
| 时序/关系消融 | 在表示层去时序或去图/血缘，在同 target 上重训 | 诊断信息贡献；会破坏攻击证据的重连/事件置乱仅作人工构造挑战，重新审核标签，不混入主自然分布 |
| 配对正常/攻击挑战 | 独立专家编写未公开 fixture，业务目标相同，仅更改授权/对象/已执行动作；固定随机化与共同观察能力 | 检验是否识别业务语境中的威胁；授权差异不可见或未实际执行时标不可判，不要求模型猜隐含权限 |
| 未见族与新模板 | 按攻击family/模板族整组隔离；公开模板与私有新模板分表 | 排查模板记忆；留族结果不能自动推广到所有威胁 |

配对挑战与语义挑战是受控诊断，不能替代低阳性率自然测试中的误报与召回。随机标签检查异常时先审计分割、缓存预测和特征泄漏，不把高分解释为泛化。

### 3.5 统计与判定

沿用 [实施计划](implementation-plan.md) 的分组CI、先导功效估计和确认前冻结规则。主比较在同一 target 上配对重采预测，以 target 的 run/用户群/episode 等独立单位为依据；外部数据没有 run 时选择实际独立采集群体，说明剩余依赖，不能伪造 run。比较多个源共享一个对照时预注册主对比并做 Holm 控制；训练seed、数据重采和独立生成run的不确定性分别报告。

原先三个主指标不因本补充自动增加大量检验。先导后为新增问题预注册一个外部来源、一个检测协议、一个主要独立基线和一个主要增强量；其余列为次级/探索性。无外部快照时 E2/E3 未测，E1 的内部相对结论可以保留。新增独立基线的确认数据不可从先导最优run挑选。

外部集只有未标注或正常数据时，可以比较正常分布与误报；没有可信攻击标签就不能计算检测AP/召回或声称威胁转移。无正例、标签范围不兼容、无法建立独立holdout的情况分别留未测原因，不通过重新平衡或补造标签修补。

“有效”不等于每个数字都更高：非劣结论用冻结的非劣界限和CI；优势/增强结论要给实用差异及CI；CI不足则 `INCONCLUSIVE`。比较的边际费用、训练量、失败率和未测能力随结果公开。

## 实施顺序、成本与交付

### 优先顺序

1. **P0/P1**：冻结共同字段与标签语义，完成外部数据可得性审计、B1/B2 输入/输出契约和独立负控制；不新增付费调用。
2. **P2**：B1/B2 先做小规模先导；核对外部 train/test、正常样本与攻击证据，估计费用和独立样本量。冻结 E1/E2/E3 主要对比、专家抽样与预算。
3. **P3**：在与 B0/B5 相同确认设计下生成所需 B1/B2 独立训练/验证run；E1 内部 target 复用冻结双域 holdout，无须为基线另造有利测试集。有外部参考再执行 E2/E3。
4. **P4**：复用标准化数据跑多检测器、增强曲线与负控制；B3/B4 在能够改变结论、资源可用时扩展。预算紧张先缩减扩展生成器和次级曲线，保留独立基线、共同target与独立人工证据。

原 8,640 员工日确认候选和约 $95.256 的新路径调用例算**不包含本补充的基线生成与新专家样本**。B1、本地统计生成器、检测重训不调用收费 LLM，但需要脚本/拟合/compute。B2 用同一可用 DeepSeek 实际型号与参数；单轮独立条件不应借助新框架历史或工具证据，所有生成、解析失败和必要重试记账。

若 B1/B2 采用每场景3训练+1验证的起步分配，则各为 `3×4×20×12=2,880` 员工日，确认增量共5,760员工日，另加各自先导；是否足够仍由独立run功效决定。B2 若每天每人一次请求、例算4,000输入+1,000输出token、Flash峰价且无缓存，2,880次约 `$6.912`，加20%请求预留约 `$8.2944`。这只算单轮日志生成，不含规划/标签审核/专家/先导/存储；长输出、thinking和重试实际usage需要重新估计。已有B0/B5规划快照可复用，不能重复收费算两次。

新增共同日志120确认包，若各做一次DeepSeek短包评分（3,000输入+600输出token，Flash峰价无缓存），约 `$0.1944`，加20%约 `$0.23328`；疑难升级、校准或外部日志另计。人工确认新增18人小时，未含校准/培训/仲裁；不可把它算进原36人小时后仍称预算不变。

等费用曲线需先声明成本口径：API、生成compute与规则/适配人工分别计量，开发一次性成本及复用摊销规则公开。仅掌握API费用时只称“等API预算”，不称等总成本；人工价格未知时保留人小时，不能把规则方法的人力当0。

交付文件为拟新增产物：`baseline_manifest.json`、`external_reference_inventory.json`、`comparison_preregistration.json`、`source_target_scores.csv`、`augmentation_curves.csv`、`negative_controls.csv`、`external_validity_report.md`。每项记录方法/版本/信息访问权、共同字段/标签证据等级、生成与训练预算、target hash、分割/阈值、预测、CI与适用范围。

最终结论分别写明：自身运行质量、相对独立生成方法的表现、在哪些外部来源有转移证据、是否有数据增强价值、哪些外部证据尚缺。没有真实企业日志时明确“尚无真实企业 TSTR 证据”，不因为通过 CERT/TWOS 或独立专家就删除该限制。
