# ChimeraLog+ 三阶段评测：数据可信、行为合理与检测效用

研究日期：2026-10-12。分支：`research/dataset-evaluation-framework`。起点：`feat/workflow-tool-execution` 的 `f218ca5`。本目录是论文调研与可实施规格；尚未实现评测程序，未执行付费模型调用或完整仿真，所有实验目标均不是实测结果。

评测沿一条主线推进：**先确认生成数据可信，再检查行为与成果是否合理，最后验证它能否支持威胁检测。** 三个阶段分别建立记录与真值、业务与真实性、检测与迁移的证据。原图的L0–L5保留为指标编号，帮助定位具体检查。

## 第一阶段：确认生成数据可信

先回答：日志、产物与攻击标签是否完整、有依据、能够追溯？

输入是原始执行日志、产物manifest、员工/任务身份、计划映射与独立攻击记录。全量检查字段、事件守恒、主键连接、时间因果、产物血缘及标签证据，并说明实际能采集哪些应用/系统/网络模态。

**交付**：可追溯的标准化数据、采集覆盖、异常/失败清单和隔离的真值sidecar。对应 **L0**。缺少证据时保留未测/不确定状态，不让模型补造事实。

## 第二阶段：检查行为与成果是否合理

再回答：可信记录中的员工是否完成了业务目标，成果是否正确，行为节奏、组织协作和内容是否合理？

从单任务扩展到整个数据集：连接计划与执行（L1）；用独立业务检查器验证成果、权限和副作用，并重复运行检查可靠性（L2）；比较条件分布、时间结构、覆盖和组织图（L3）；以专家盲评和经过校准的DeepSeek辅助评分确认语义真实性（L4）。

**交付**：业务成果与失败诊断、分布/覆盖报告、独立人工评分，以及已验证和未测范围。对应 **L1–L4**。正常行为和预定攻击分别解释；失败、少数角色及被阻断攻击保留。

## 第三阶段：验证能否支持威胁检测

最后回答：用这份数据训练检测器，能否在独立测试中发现威胁，并支持跨场景或新攻击族的检测？

从前两阶段数据中提取检测时可见的特征，隔离真值与标签捷径。旧/新数据训练的检测器都在同一批持有数据上测试，报告AP、固定审查预算下的召回、误报、攻击episode召回与日终报警延迟，并检验迁移和稳健性。

**交付**：带置信区间的检测效用报告及适用范围。对应 **L5**。CERT/旧ChimeraLog上的测试称合成转移；TWOS称人类竞赛数据转移；真实企业持有集才支持TSTR结论。

## 全流程的质量与成本原则

每项结果保留数值、分母、95%区间、证据定位和 `PASS / FAIL / INCONCLUSIVE / NOT_MEASURED / NOT_APPLICABLE`。分别报告三个阶段的证据，不合成一个总分，也不以检测高分抵消数据或业务错误。

结构、血缘、权限、业务数值和统计检查尽量本地全量完成。所有模型辅助评测只用DeepSeek；语义证据包采用低价型号初评、疑难升级，并保留随机独立人工确认。复用标准化数据、特征和预测，分别记录生成、模型评审、人工与检测计算费用；控制费用时保留质量要求。

分布距离、语义真实性和检测效用通过先导实验、参考自身波动、预注册差异界限与置信区间判断。原图的 `KS ≤0.10`、`F1 ≥0.80` 等不是文献证明的通用门槛。

## 当前接口限制与研究证据

本分支已有阶段规划、任务级文件系统工作流、日志抽取和产物manifest。新路径需 `CHIMERA_WORKFLOW_EXECUTION=1`。工具事件的统一时间/序号/业务成功字段、计划活动关联和跨任务共享证据仍需补齐；本地JSON凭证不能证明真实外发或系统捕获。第一阶段先处理这些观测缺口，第二阶段再验证成果内容。

`dev` 的初步评测适配另一版原型，未直接合入这里。指标和实施适配以当前分支接口为准。
