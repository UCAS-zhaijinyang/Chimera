# ChimeraLog+ 评测体系：从数据可信到检测效用

状态：设计规格，未执行实验。基于 `f218ca5` 的真实接口，沿用用户图中的 L0–L5 编号。论文编号见 [调研](literature-review.md)；落地顺序见 [实施计划](implementation-plan.md)。

## 评测主线

先确认生成数据可信，再检查行为与成果是否合理，最后验证它能否支持威胁检测。三个阶段分别建立“记录与真值”“业务与真实性”“检测与迁移”的证据。L0–L5保留为指标索引，正文按评测问题组织。

| 阶段 | 要证明什么 | 对应指标 | 输入 → 输出 |
|---|---|---|---|
| 第一阶段：确认生成数据可信 | 数据完整、可连接，标签有实际证据 | L0 | 原始日志/产物/攻击记录 → 可追溯数据与采集能力清单 |
| 第二阶段：检查行为与成果是否合理 | 任务、成果、时序、组织协作及内容合理 | L1–L4 | 第一阶段数据+计划/参考/业务规则 → 业务与真实性评测报告 |
| 第三阶段：验证能否支持威胁检测 | 没有标签捷径，检测有效且可迁移 | L5 | 前两阶段证据+独立持有集 → 效用与适用范围报告 |

三阶段是结论的证据顺序。错误诊断可以并行开展；数据分割、阈值、主要指标与预算要在确认实验前预注册。阶段缺失证据时保留未测/不确定状态，不能由后续高分抵消。

采用共同规则：硬约束来自采集/任务契约；统计目标与差异界限由先导实验校准。每项输出数值、分母、95%区间及证据定位，不合成一个总分。数据单位和完整输出契约见附录A，原图指标的修订说明见附录B。

## 第一阶段：确认生成数据可信

**核心问题**：记录是否完整、能否从员工和计划连接到工具调用及产物，攻击标签是否对应可观察行为？

输入是不可变原始日志、产物manifest、公司/员工档案、计划映射和隔离的攻击真值。先明确各run能观察哪些模态，再检查记录守恒、主键、时间因果、血缘和真值证据。

交付可追溯的标准化数据、采集覆盖清单、异常记录与标签状态。数据可信表示“后续评价有可靠依据”；真实性与检测效用分别在第二、三阶段证明。

### 1.1 L0：可观测性、数据完整性与真值

依据：P01/P02/P14/P23/P24。先保存不可变原始数据，再构建标准化评测层，最后衍生检测特征。

| ID / 指标 | 计算与分母 | 数据与证据 | 判定 |
|---|---|---|---|
| L0.1 核心字段可用率 | 可解析且有必需核心字段的记录 / 所有预期记录；另报每字段缺失 | 原始日志、预期文件清单、schema；不要只统计抽取器留下的行 | 核心记录 100%；失踪/损坏必须显式失败并保留 |
| L0.2 主键关联完整性 | 可唯一连接 run/member/task/call 的事件 / 所有事件；重复/孤儿计数分列 | run manifest、profile、任务 sidecar、原始日志 | 100% 核心连接；不得通过解析 trace 字符串猜测替代契约 |
| L0.3 文件与事件守恒 | 原始候选标记行数 = 标准化行数 + 有原因拒绝行数；每调用有 started 和 terminal 或 timeout | 原日志 byte offset/line、parse rejection 表、调用 ledger | 等式闭合；所有异常有记录；损坏攻击记录独立统计 |
| L0.4 产物血缘完整性 | 输入存在且版本合法的必需依赖边 / oracle 规定的全部依赖边；另报悬空边与环 | 各 workspace manifest、文件 hash、工具契约 | 必需边 100%、悬空边/非法环 0；明确合法根 |
| L0.5 因果与时间约束 | 无法解释的先消费后生产、负持续时间、错误员工/阶段数 | simulation_time、wall_time、event_seq、依赖边 | 硬因果冲突 0；并行与缺失时钟单列，不做全局排序假设 |
| L0.6 标签可追溯性 | 有 episode、角色与证据指针的阳性标签 / 所有阳性；意图/尝试/执行/证据分别计数 | 攻击 manifest、执行事件、收集事件、标签 sidecar | 发布 positive 标签 100% 有适配层证据；未知不能改成阴性 |
| L0.7 跨采集源对齐 | 命中应用/系统/网络证据的预期 checkpoint / 该源可观测的 checkpoint | tool event、artifact、email/file/http、pcap/scap；时钟对齐误差 | 有采集才测；JSON 凭证只算模拟应用证据，不能冒充 pcap |
| L0.8 发布完整性/泄漏扫描 | 凭证/非虚构个人信息/标签路径候选与人工确认数 | 原始/发布副本、配置脱敏表、近重复清单 | 实际凭证与公开标签捷径 0；PII 候选复核；不声称 DP |

标签契约：`intent_status`（planned/cancelled）、`attempt_status`（not_attempted/attempted/blocked）、`execution_status`（succeeded/failed/unknown）、`observation_status`（observed/unobserved）、`evidence_level`（simulation_only/application/system/network）。“被阻断恶意尝试”和“成功恶意执行”分别构成检测子任务，不能混成一个成功攻击指标。用户日标签表示当日有某类恶意证据，不能向整日所有正常事件传播。

### 1.2 阶段结论与交接

核心主键、事件守恒和发布阳性标签必须有证据；坏行、丢失、失败与unknown显式留存。具备核心契约且公开采集范围，才能以对应数据支持下一阶段结论；缺失模态标NOT_MEASURED，不由模型补造。

例如报告任务在这里确认输入记录、工具调用、报告文件和交付对象是否真的存在并能连接。报告里的聚合数字是否正确，进入第二阶段独立检查。

## 第二阶段：检查行为与成果是否合理

**核心问题**：可信记录中的员工行为是否符合业务目标，成果是否正确，群体行为和组织协作是否合理？

从单任务到整个数据集逐步检查：计划与执行对应（L1）→独立业务终态与副作用（L2）→条件分布、时间结构和覆盖（L3）→人工确认的语义与组织真实性（L4）。正常与预定攻击分别解释，保留失败轨迹。

输入是第一阶段可追溯数据、计划、任务oracle、组织/权限规格与可得参考集。输出业务成功/失败原因、分布与覆盖诊断、独立人工评分及证据边界。

### 2.1 L1：计划—执行一致性与业务约束

依据：P01/P02/P17。依赖阶段计划、每日安排及执行活动的稳定映射。`final_schedule.csv` 是计划上下文，不是行为真值。

| ID / 指标 | 计算与分母 | 数据与解释 | 判定 |
|---|---|---|---|
| L1.1 工作单元匹配 P/R/F1 | 合并同一活动的多工具调用为 executed work unit；与 planned work unit 一对一匹配，`P=m/E, R=m/Pn, F1=2PR/(P+R)` | sidecar 确定映射；语义模糊映射单独人工复核，不按文本相似度自动算完成 | 诊断，与基线/预注册目标比较；不要用调用数量放大匹配 |
| L1.2 计划目标完成率 | 满足独立 completion oracle 的计划目标 / 所有到期计划目标 | 计划 goal_id、任务终态；延期/取消只有正式变更才移出到期分母 | 业务成功主指标；重试不重复计成功 |
| L1.3 阶段与时间偏差 | 提前/延迟/错阶段 work unit 比例；deadline slack 分布 | phase ranges、约定交接期、实际模拟时间 | 硬阶段约束 0 违规；软期限按类型/角色报告，不统一 0 |
| L1.4 handoff 正确率 | 内容正确、身份授权且生产先于消费的 handoff / 所有规定 handoff | producer/consumer、artifact 版本、task dependency；收件人 ACL | 硬因果/对象错误 0；业务延期另报 |
| L1.5 计划外行为组成 | 批准变更/协作/浏览/恶意/无法解释数量分别除以实际工作单元 | 动态 schedule revision、执行日志、attack sidecar | 未解释比例校准；攻击不算执行失真 |
| L1.6 多日连续性 | 后续正确使用前日结果的任务 / 全部需要跨天依赖的任务 | 跨 task workspace 索引、版本/引用 | 目前未完整实现→NOT_MEASURED；另报遗忘/重复生产 |

在没有 `planned_activity_id` 的旧导出上，只做“可观察的匹配子集”；注明 coverage。禁止把缺失映射的全部行为算正常匹配，也不能把工作流 final answer 当 completed activity。

### 2.2 L2：工具工作流终态、策略与重复可靠性

依据：P15/P16/P17。针对实际 `WORKFLOWS` 评 state transition，旧 `ToolGraph` 可作为类型接口参考，但不能拿其边替代新 runner 的允许状态表。

| ID / 指标 | 计算与分母 | 数据与解释 | 判定 |
|---|---|---|---|
| L2.1 合法尝试与拒绝覆盖 | 状态机允许的调用尝试 / 全部调用尝试；状态机禁止尝试中正确拒绝 / 所有该类尝试 | 直接读原始 success/failed/rejected；同一步多调用按 event_seq，不只读成功转移 CSV | **状态机禁止或越出隔离仿真技术范围的执行数0**；黄金拒绝用例全部拒绝；业务政策违规另在L2.6解释 |
| L2.2 任务业务终态成功率 | 目标 oracle 全满足且无禁止副作用的任务 / 全部分配任务 | 任务前后 snapshot、独立检查器、timeout/模型提前结束均留分母 | 初期点估计目标 ≥90%仅是候选；正式与基线差异及 CI 判定 |
| L2.3 检查点完成率 | 达成 checkpoint 数 / 规定 checkpoint 数；另报每任务是否全完成 | 数据报告的聚合/文件/存储/收件人；开发的复现/功能测试/审批证据 | 诊断定位卡点；部分分不能替代完整成功 |
| L2.4 内容与血缘链成功 | 输入—变换—正确成果—交付一致的链 / 全部需要该链的任务 | 文件内容、输入 hash、output artifact、收件人可读性 | 必需链正确才算终态成功；“inputs 非空”本身不够 |
| L2.5 collateral damage | 禁止变更对象数、发生破坏的任务比例 | 前后 allowed-write-set diff；ACL 前后值 | 正常任务禁止副作用 0；预定攻击改动单独验证目标/范围 |
| L2.6 政策与越权 | 正常未授权成功次数；恶意尝试/成功/阻断；合法交付中接收者可读率 | actor ACL、对象敏感度、请求与真实执行、授权规范 | 正常越权 0；攻击目标按 episode 定义，不以所有违规 0 为门禁 |
| L2.7 重复稳定性 | 每任务 n 次，c 次 oracle 成功：`pass^k=mean_task[C(c,k)/C(n,k)]`，c<k为0 | 固定初始环境、独立模型采样/请求；n≥k；重置所有文件和状态 | n=3 报 pass^1/pass^3，区间按任务聚类；不是 `pass@k` |

`pass^3` 只诊断黄金任务重复可靠性，不等同于全数据集“稳定”。独立 run、不同组织/任务及数据统计的漂移另在 L3/L5 评。模型温度 0 也可能非确定，固定参数不代表复现了同一次随机样本。

三类规则分开：`technical_allowset`定义状态机与隔离环境允许执行的工具/对象范围；`business_policy`定义正常业务授权；`attack_spec`定义该episode拟模拟的恶意目标与允许影响对象。成功的预定攻击可以在technical_allowset内违反business_policy，但必须符合attack_spec且保留违规标签。状态机违规、逃出隔离范围、破坏attack_spec以外对象均不能被“这是攻击”豁免。若当前allowset不能模拟某类成功攻击，就只评被阻断尝试或标能力缺失，不改门禁偷偷放行。

### 2.3 L3：条件分布保真、时间结构、多样性与覆盖

依据：P06–P13/P18/P19。参考按证据强弱标记：真实授权企业数据、TWOS 人类竞赛数据、CERT 合成数据、旧 ChimeraLog 合成数据、组织/工作流规格。它们各自验证不同问题，不能互相替代。

| ID / 指标 | 计算与分母 | 数据与解释 | 判定 |
|---|---|---|---|
| L3.1 边际与条件距离 | 连续变量 KS=`sup\|F_G−F_R\|`；`W1_norm=W1/IQR(reference_train)`；类别 TV=`0.5Σ\|pG−pR\|` | 共同 user-day 特征；按 role/department/phase/benign 分层，IQR=0时单独处理 | 对比 R/R 拆分自然距离 + 预注册容忍差；不是统一≤0.10 |
| L3.2 时间结构 | 工作时段直方图 TV、间隔分布距离、预注册 lag 的 ACF MAE、任务状态转移分布 JS | simulation_time，保留工作日周期、跨天与同员工相关 | 与 matched reference 比，异常攻击不要求复制正常分布 |
| L3.3 关系结构 | 共同数值特征 Spearman 矩阵非对角元素 MAE；类别关联单列 | 去身份/路径字段、固定特征与缺失策略、分层 | 基线/参考校准；相关性不代表因果 |
| L3.4 来源可分性 C2ST | 分组交叉验证的来源 ROC-AUC；报告 `AUC_sym=max(AUC,1−AUC)` | 仅正常共同字段；去路径/run ID/格式/新字段；来源均衡 | 高值提示 domain shift，不能单独判假；负控制应接近0.5 |
| L3.5 覆盖与模式塌缩 | 应有 role×phase×workflow 单元覆盖数/可行单元数；每单元任务数；β-Recall为可选深评 | 可行单元来自规格；空角色、稀有攻击、工具与任务簇 | 必需单元100%覆盖；其余阈值先导校准，按最差组报告 |
| L3.6 重复与抄模板 | 重复记录比例 `(N−unique)/N`；固定规范化的 MinHash/词n-gram近重复簇与最大簇占比 | 屏蔽ID/时间但不抹掉行为内容；例行固定文本单列 | 诊断；不能把合法周期任务一律算失败，不叫 Authenticity |
| L3.7 图结构 | 组内边密度/组间边密度、已指定 handoff 命中率、隔离点、度/聚类统计；多独立图才算 MMD | 有向边由可验证邮件/消息/产物消费产生；会议名单不是实际交流边 | 规格一致性+匹配 null 对照；无真实图不声明真实保真 |
| L3.8 run 漂移 | 同配置不同run间各关键统计/任务成功的均值、方差、最差run | 不同运行的共同特征、失败率、角色覆盖 | 差异与区间；不能靠重跑后只留最好run |

组内潜在有向边数 `Oin=Σd nd(nd−1)`，组间 `Oout=N(N−1)−Oin`，无自环；`density_in=unique_in/Oin`，`density_out=unique_out/Oout`。比率分母零时不强行计算。消息重复次数用加权图补充，不能混进 unique density。保度重连的随机 null 是统计对照，不是“真实企业”。

距离校准：从参考的独立 run/员工组构造匹配大小 R1/R2，在校准集形成各特征 `D_RR` 分布；冻结分箱/尺度/容忍界限后测 `D_GR`。仅一个参考run或TWOS短窗口时，指出其局限，不能声称参考容忍区间稳定。全局均值与最差角色/阶段同时报告。

### 2.4 L4：语义与组织真实性、人工与 DeepSeek 校准

依据：P01/P12/P20/P21。评分单位是含任务、角色、计划片段、工具证据和成果的短轨迹包，补充孤立日志评分用于与原论文比较。

| ID / 指标 | 计算与分母 | 数据与解释 | 判定 |
|---|---|---|---|
| L4.1 人工分维度 Likert | 内容业务可信/角色与能力/时间与协作/成果可核验四维1–5，分别均值、分布、95%CI | 随机分层盲评，失败轨迹保留；证据不足可 abstain | 候选 non-inferiority margin 0.25/5；相对基线差异CI为依据，不能只要求均值4 |
| L4.2 人工一致性 | 每维 ordinal Krippendorff α=`1−Do/De`、聚类bootstrap CI，另报缺失/abstain | 每包≥3人、隐藏来源与模型；保留争议与原始评分 | ≥0.80较可靠；0.67–0.80暂定；更低重校准，均为工作标准非保证 |
| L4.3 严重语义缺陷 | 确认的虚构结果/角色越界/错误交接/矛盾数除有效评审包 | 证据引用、缺陷 taxonomy，按良恶/角色分别 | 对照缺陷率及CI；严重输出错误接回L2业务oracle |
| L4.4 评审模型有效性 | 模型与独立专家的ordinal误差/κ、pairwise一致率、严重缺陷漏判率 | 独立随机校准/确认样本；按来源、长度与角色检查误差 | 不合格模型降为候选定位；不能替代人工主指标 |
| L4.5 组织行为一致性 | 授权角色/阶段/任务指定handoff一致事件 / 有明确约束的可评价事件 | 显式规范+人工核查，允许正常应急协作 | 硬规范用自动检查；模糊真实性人工评分，分开报告 |

成本限制不能将所有真人标注变成模型重复投票。DeepSeek 强模型升级解决单次能力不足，无法证明已消除共同厂商偏好。完整量表、盲化和提示词见 [评审协议](judge-and-cost.md)。

### 2.5 阶段结论与交接

报告必须同时列任务成果、正常/恶意行为、角色覆盖、时间与协作、语义评分。分布距离和人工评分通过参考与置信区间解释，不能只用固定数字宣布“像真实企业”。

例如报告任务要检查聚合数字、报告内容、附件引用与接收者权限；跨多个员工/工作日再检查是否人人产生同一种报告、协作是否符合任务需要。将适用模态、已验证范围及失败/未测项一并交给第三阶段。

## 第三阶段：验证能否支持威胁检测

**核心问题**：使用这些数据训练检测器，能否在独立测试中发现威胁，并在固定审查预算和跨场景条件下保持效用？

输入为前两阶段评测证据、隔离真值后的可观察特征、冻结的训练/验证/测试分割与告警预算。比较旧/新数据训练的检测器在同一持有集上的结果，并分别验证标签捷径、跨场景迁移和表示增益。

输出检测效用、迁移范围、不确定性与局限。普通任务成功不能替代威胁检测证据；测试目标的来源决定最终可声称的效用范围。

### 3.1 L5：下游检测效用、无泄漏转移与运营指标

依据：P01/P05/P13/P14/P25。主任务默认用户日威胁检测，辅助任务 episode 与证据检索。先冻结标签语义、时间窗口和可观察信息范围。

| ID / 指标 | 计算与分母 | 数据与解释 | 判定 |
|---|---|---|---|
| L5.1 AP / PR曲线 | 用检测连续分数算average precision；同时报阳性率、正例数、ROC-AUC与MCC | 未重平衡测试集、grouped holdout；AP不等于任意梯形PR-AUC | 同一测试上新/旧训练数据差异CI；无正例则NOT_MEASURED |
| L5.2 固定预算召回 | `Recall@k=topk命中正例/全部正例`；`ER=Precision@k/prevalence` | 单位固定员工日或用户，k按实际审查预算预注册 | 新vs旧差异；ER高也需报命中正例数与区间 |
| L5.3 FPR 与事件召回/延迟 | `FPR=FP/(FP+TN)`，每千正常员工日报警；episode召回=有及时报警episode/所有可观察episode | 主实验只在日终获得user-day分数，报警时间按日终；另做滚动实验才可报事件级早检 | 固定FPR/预算下的召回；延迟从first evidence到日终first alert，未检出按删失，不回填到首条异常时间 |
| L5.4 无泄漏元数据诊断 | metadata-only标签AP；比较完整/去元数据/随机标签/去注入文案的结果 | 只输入检测时可见字段；run/path/attacker标识/计划文字/oracle结果禁止 | 明确可疑捷径必须修；不能用一个AUC阈值机械判定 |
| L5.5 共同测试转移效用 | 同一target_holdout上的 `ΔAP=AP(train_new)−AP(train_old)`，`ΔRecall@k` | 同观察模态、匹配训练正常量、标签口径，target与生成调参隔离 | 候选AP非劣界限0.02，须先导校准；不可只比两个不同测试集的F1 |
| L5.6 跨场景/新攻击族 | 留场景、留攻击族测试；同单位报告 `drop=source−target`及差异 | 不同环境、任务模板/攻击family分组；输入只能是可观察记录 | 正式CI；缺场景/攻击族则不宣称泛化 |
| L5.7 表示增益与稳健性 | 共同user-day特征 vs 加血缘/组织图；正常模态缺失/时钟误差下的性能差 | 共用holdout、固定训练预算、预注册缺失率与噪声 | 新字段增益及抗扰动诊断；不重新调用LLM生成数据 |

同分布新数据测试只能回答“该分布下可学”，不是外部真实效用。TSTR、S→S 和 S→human-collected 在所有图表与表格中分别命名。没有授权真实日志时，最终发布卡明确写“尚无真实企业 TSTR 证据”。

可选在线延迟实验固定滚动评分间隔（如30模拟分钟），只用截至评分时刻的证据，特征窗口与阈值均在训练/验证阶段冻结。不得用全日特征产生的分数声称上午已检出；日终实验的延迟只能解释为批处理延迟。

### 3.2 阶段结论与交接

分别报告AP、预算召回、误报、episode召回/日终延迟，以及同一target上新旧训练方案的差异区间。元数据和预定攻击文案不能作为检测捷径。

前述报告任务若包含预定外发攻击，这里检验检测器能否在可观察证据上发现外发，在正常业务交付上控制误报。没有真实企业持有集时，最终结论限定为合成转移或人类竞赛数据转移。

## 全流程结论与发布范围

不将六层分数相加，不把某层提升抵消另一层硬错误。

1. **工程可观测集**：L0核心契约闭合，记录业务失败和采集覆盖；L1/L2证据可复算。可用于调试，不能宣称真实/有效。
2. **受控仿真基准**：黄金oracle、所需角色/工作流/攻击覆盖、失败保留、L3诊断与人工盲评可用，所有未测维度明确标出。
3. **有转移效用证据的数据集**：在共同独立测试上完成L5、排除标签捷径，报告差异CI；若目标仅合成/竞赛数据，结论范围随之限定。
4. **具有真实企业效用证据**：另有授权真实持有集上的TSTR与用途约束；本方案不默认具备此证据。

候选目标必须在确认集揭盲前冻结。CI跨越差异界限→INCONCLUSIVE；点估计好看不能改成PASS。诊断发现错误→修复后使用新的确认run，旧失败及版本差异继续保留。

## 附录A：共同数据单位与结果契约

| 评测单位 | 唯一标识（待采集契约补齐） | 主要用途 |
|---|---|---|
| 事件/工具尝试 | `(run_id, event_id)`，`call_id` | 完整性、权限、时序、失败 |
| 产物及版本 | `(run_id, workspace_id, artifact_id, version)` | 血缘、内容、终态和副作用 |
| 任务轨迹 | `(run_id, member_id, task_id)` | 计划对齐、业务成果、可靠性、语义 |
| 员工日 | `(run_id, member_id, workday)` | 频率/时段、检测特征、报警预算 |
| 攻击 episode | `(run_id, episode_id)` | 意图/执行/证据、检测延迟与覆盖 |
| 组织周/阶段图 | `(run_id, phase_id, time_window)` | 跨角色/部门协作 |

`trace_id` 目前包含员工、周、星期和 task index，但在不同 run 中会重复；不能用它当全局主键。事件 wall-clock 时间与模拟业务时间分开，跨进程先按调用序号/因果边比较，不能要求整文件写入顺序全局时间递增。

所有指标输出 `metric_id, version, scope, value, numerator, denominator, unit, ci95, status, reason, evidence_refs, reference_id`。比率分母为零是 `NOT_APPLICABLE` 或采集不足 `NOT_MEASURED`；绝不默认为 100%。缺少证据时不记为失败业务，但应使对应质量结论 `INCONCLUSIVE`。

## 附录B：原图指标的修订说明

| 原图设定 | 修订 | 原因 |
|---|---|---|
| 必填字段 ≥99.5%、关联率 ≥99% | 核心主键/真值字段 100%；可选字段按声明报告缺失率 | 少量缺失若集中在攻击会严重偏置，不能以均值掩盖 |
| 所有产物都必须有 inputs | 根产物可为空且必须声明根类型；需要输入的工具检查预期输入边 | ticket/source 是合法根；空血缘不一定是错误 |
| 时间、权限、攻击证据违规均为 0 | 不可解释的记录冲突为 0；正常越权、攻击尝试、攻击执行分别报告 | 模拟攻击产生违规正是数据目的 |
| 所有 handoff/阶段越界为 0 | 对硬因果边禁止先消费后生产；对业务截止日期分软/硬约束 | 延期、应急任务是可能合理的企业行为 |
| 计划外行为 ≤10% | 分批准变更、协作、浏览、攻击、未知；未知比例校准 | 攻击与临时任务不应被误当低质量 |
| 合法工具转移 100% 即质量高 | 同时报非法尝试被拒绝率、业务成功和终态 | 路由器强制合法使该指标可能只是机制自证 |
| KS/Wasserstein 都 ≤0.10 | KS 无量纲；Wasserstein 明确尺度；参考自身分割校准差异范围 | 不同特征/单位不能共享同一阈值 |
| AUC ≤0.65、重复率 ≤5% | 用校准集、匹配样本、来源双向可分性和重复簇规模诊断 | 字段新增与常规业务模板不等于不真实 |
| 组内协作/跨组协作 >1 | 按组内/组外潜在边数归一化并比较 matched null | 部门大小与任务跨部门需求会改变机会数 |
| TSTR/Real-to-Real F1 ≥0.80 | 合成转移与真实转移分开；主要比较 AP 与预算召回的差异 | 没有真实数据不算 TSTR，F1 依赖基准与阳性率 |
| 跨场景下降 = 目标−来源 ≤20pp | 若保留下降概念，定义 `source_score−target_score`；正式比较目标测试上的两训练方案 | 原符号会令所有下降自动满足上限 |
| 元数据预测来源 AUC ≤0.60 | 分开来源可分性与恶意标签泄漏 | 能分辨生成来源不等于预测标签捷径 |
| 逐层全部通过才测上一层 | L0 的可用性影响可信结论；各层诊断可并行，限制发布宣称 | 失败数据仍需诊断，不能只评价存活样本 |

下面“硬门禁”是契约规则；“目标/差异界限”是本方案建议，需要先导实验预注册；“诊断”不单独决定发布。没有文献证明上述数字是普适阈值。
